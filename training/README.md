# Training Data for Hush Engine

This directory contains training feedback collected from the Hush macOS app and benchmark results to improve PII detection accuracy.

## Directory Structure

```
training/
├── README.md                    # This file
├── analysis/                    # Analysis outputs
│   ├── analysis_*.json          # Timestamped analysis reports
│   ├── claude_actions.json      # Actionable improvements for Claude
│   └── processed_feedback.json  # Tracks which feedback has been processed
└── feedback/                    # Feedback and benchmark data
    ├── feedback_*.json          # Individual user feedback entries
    ├── benchmark_*.json         # Benchmark run results
    └── archived/                # Processed feedback archive
        └── batch_*/             # Timestamped batch archives
```

## Feedback Format

Each feedback file is a JSON document with the following structure:

```json
{
  "timestamp": "2026-02-02T16:46:35.000Z",
  "fileName": "document.pdf",
  "filePath": "/Users/.../document.pdf",
  "detectedText": "John Smith",
  "detectedEntityType": "PERSON",
  "bbox": {
    "x": 100.0,
    "y": 200.0,
    "width": 150.0,
    "height": 20.0
  },
  "page": 1,
  "confidence": 0.85,
  "suggestedEntityTypes": ["PERSON", "COMPANY"],
  "notes": "User notes about the detection",
  "engineVersion": "1.3.0"
}
```

### Fields

| Field | Type | Description |
|-------|------|-------------|
| `timestamp` | ISO 8601 | When the feedback was submitted |
| `fileName` | string | Name of the processed file |
| `filePath` | string | Full path to the file (for reference only) |
| `detectedText` | string | The text that was detected |
| `detectedEntityType` | string | What the engine classified it as |
| `bbox` | object | Bounding box coordinates (nullable) |
| `page` | int | Page number for PDFs (nullable, 1-indexed) |
| `confidence` | float | Engine's confidence score (0.0-1.0) |
| `suggestedEntityTypes` | array | User's suggested correct entity types |
| `notes` | string | Free-form user notes |
| `engineVersion` | string | Version of hush-engine that made the detection |

## Entity Types

Valid entity types that may appear in `detectedEntityType` or `suggestedEntityTypes`:

**Personal Identity**: `PERSON`, `FACE`, `GENDER`, `AGE`, `NRP`
**Contact Information**: `EMAIL_ADDRESS`, `PHONE_NUMBER`, `URL`
**Government IDs**: `SSN`
**Financial**: `CREDIT_CARD`, `FINANCIAL`, `AWS_ACCESS_KEY`, `STRIPE_KEY`
**Location**: `LOCATION`, `COORDINATES`
**Medical**: `MEDICAL`
**Technical/Device**: `IP_ADDRESS`
**Document Elements**: `DATE_TIME`, `QR_CODE`, `BARCODE`
**Organization**: `COMPANY`, `ORGANIZATION`
**Other**: `CUSTOM`, `UNKNOWN`

## Benchmark Files

Benchmark files (`benchmark_*.json`) are generated by running `tests/benchmark_accuracy.py`. They follow the same schema as feedback files but contain automated test results:

- `notes` field contains `"Benchmark (csv): missed detection"` or similar markers
- `confidence: 0.0` indicates a missed detection
- `detectedEntityType: "CUSTOM"` indicates the engine didn't detect the expected type

## Using Feedback for Training

### 1. Analyze Feedback Patterns

Look for common patterns where the engine made mistakes:

```python
import json
from pathlib import Path
from collections import Counter

feedback_dir = Path("training/feedback")
misclassifications = Counter()

for file in feedback_dir.glob("*.json"):
    with open(file) as f:
        entry = json.load(f)
        detected = entry["detectedEntityType"]
        suggested = entry["suggestedEntityTypes"]

        if detected not in suggested and suggested:
            misclassifications[(detected, tuple(suggested))] += 1

print("Common misclassifications:")
for (detected, suggested), count in misclassifications.most_common(10):
    print(f"  {detected} -> {suggested}: {count}")
```

### 2. Extract Training Examples

Generate training data for specific recognizers:

```python
# Extract false negatives (missed detections)
false_negatives = []
for file in feedback_dir.glob("*.json"):
    with open(file) as f:
        entry = json.load(f)
        if entry["detectedEntityType"] == "UNKNOWN" and entry["suggestedEntityTypes"]:
            false_negatives.append({
                "text": entry["detectedText"],
                "entity_type": entry["suggestedEntityTypes"][0],
                "notes": entry["notes"]
            })
```

### 3. Adjust Confidence Thresholds

Use feedback to tune per-entity confidence thresholds:

```python
# Analyze confidence scores for correct vs incorrect detections
correct_confidences = []
incorrect_confidences = []

for file in feedback_dir.glob("*.json"):
    with open(file) as f:
        entry = json.load(f)
        detected = entry["detectedEntityType"]
        suggested = entry["suggestedEntityTypes"]
        confidence = entry["confidence"]

        if detected in suggested:
            correct_confidences.append((detected, confidence))
        else:
            incorrect_confidences.append((detected, confidence))
```

## Archiving Processed Feedback

After processing feedback, move files to the `feedback/archived/` directory:

```bash
# Create a batch archive
mkdir -p training/feedback/archived/batch_$(date +%Y-%m-%d_%H-%M-%S)
mv training/feedback/feedback_*.json training/feedback/archived/batch_*/
```

The `/clear-feedback` skill automates this process, moving processed feedback to timestamped batch folders.

## Best Practices

1. **Archive, don't delete** - Move processed feedback to `archived/` with batch timestamps
2. **Track by engine version** - Filter feedback by `engineVersion` to measure improvements
3. **Preserve privacy** - The `filePath` field is for reference; don't store actual file contents
4. **Batch processing** - Process feedback periodically rather than in real-time
5. **Run benchmarks** - Use `python3 tests/benchmark_accuracy.py` to generate benchmark feedback

## LightGBM/SVM Model Training

The Hush Engine includes trainable NER models for PERSON, ADDRESS, LOCATION, DATE_TIME, and ORGANIZATION detection.

### Training Commands

```bash
# Train a single entity type with synthetic data
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --samples 5000

# Train with SMOTE class balancing (recommended)
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --samples 5000 --smote

# Train with noise augmentation (PMC paper approach)
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --samples 5000 --augment

# Train with both SMOTE and augmentation
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --samples 5000 --smote --augment

# Train using ai4privacy external dataset
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --ai4privacy --samples 10000

# Train all entity types
python3.10 tools/train_lgbm_ner.py --all --samples 5000 --smote

# Use SVM classifier instead of LightGBM
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --classifier svm --samples 5000
```

### Training Options

| Flag | Description |
|------|-------------|
| `--entity-type` | Entity type to train (PERSON, ADDRESS, etc.) |
| `--all` | Train all entity types |
| `--samples N` | Number of training samples (default: 5000) |
| `--smote` | Apply SMOTE oversampling to balance classes 1:1 |
| `--augment` | Apply noise augmentation (punctuation, OCR errors) |
| `--ai4privacy` | Use ai4privacy external dataset |
| `--classifier {lgbm,svm}` | Classifier type (default: lgbm) |
| `--seed N` | Random seed for reproducibility |

### SMOTE Class Balancing

SMOTE (Synthetic Minority Over-sampling Technique) addresses class imbalance by synthesizing new positive examples. Literature shows SMOTE achieves 96% accuracy vs 70% with undersampling.

```bash
pip install imbalanced-learn
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --smote
```

### SVM Alternative

SVM with RBF kernel is an alternative to LightGBM that may generalize better on some datasets. Outputs are saved as `.pkl` files.

```bash
python3.10 tools/train_lgbm_ner.py --entity-type PERSON --classifier svm

# Output files:
# hush_engine/models/lgbm/person_svm.pkl
# hush_engine/models/lgbm/person_scaler.pkl
# hush_engine/models/lgbm/person_metadata.json
```

### Preparing External Training Data

Convert ai4privacy dataset to training format:

```bash
# Convert full dataset with sentence extraction
python3.10 tools/convert_ai4privacy.py --all \
    --extract-sentences \
    --negative-rate 0.15 \
    --output tests/data/ai4privacy/sentences

# Convert specific entity type
python3.10 tools/convert_ai4privacy.py --entity-type PERSON \
    --max-samples 20000 \
    --output tests/data/ai4privacy
```

### Model Output Location

Trained models are saved to `hush_engine/models/lgbm/`:
- `{entity}_classifier.txt` - LightGBM model
- `{entity}_metadata.json` - Training metadata
- `{entity}_svm.pkl` - SVM model (if using --classifier svm)
- `{entity}_scaler.pkl` - Feature scaler for SVM

## Threshold Calibration

Use Yellowbrick-style precision-recall analysis to find optimal thresholds:

```bash
# Generate clean synthetic benchmark data first
python3.10 tools/create_synthetic_golden.py --samples 1000

# Run calibration with visualization
python3.10 tools/calibrate_thresholds.py \
    --dataset tests/data/synthetic_golden.json \
    --samples 500 \
    --visualize

# Output Python config code
python3.10 tools/calibrate_thresholds.py \
    --dataset tests/data/synthetic_golden.json \
    --output-python
```

Calibration plots are saved to `training/analysis/calibration_plots/`.

## Synthetic Benchmark Data

The `create_synthetic_golden.py` tool generates clean PII data using Faker. This provides:
- **Consistent format**: Standard US phone numbers, SSNs, addresses
- **No OCR noise**: Clean text without corruption
- **Reproducible results**: Fixed random seed for deterministic benchmarks

```bash
# Generate 1000-sample synthetic golden set
python3.10 tools/create_synthetic_golden.py --samples 1000 --seed 42

# Run benchmark on synthetic data
python3.10 tests/benchmark_accuracy.py --golden --no-pdf
```

**Expected performance on synthetic data**: 82% F1 (vs 70% on legacy noisy datasets).
